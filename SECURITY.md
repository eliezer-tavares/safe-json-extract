# Security Policy

## Supported Versions

The following versions of **safe-json-extract** are currently supported with security updates:

| Version | Supported |
|--------|----------|
| 1.x    | Yes      |

Future major versions may introduce breaking changes, but security fixes will always be prioritized for the latest stable release.

---

## Reporting a Vulnerability

If you discover a security vulnerability in this project, **please do not open a public issue**.

Instead, report it privately using one of the following channels:

- GitHub Security Advisories (preferred)
- Direct email contact with the maintainer

📧 Email: contact@eliezertavaresdeoliveira.com

---

## What to include in a report

To help us investigate and respond quickly, please include:

- Clear steps to reproduce the issue
- Description of the potential impact
- Example input that triggers the vulnerability (if applicable)
- Suggested fix or mitigation (optional but appreciated)

---

## Response Policy

All security reports will be:

- Acknowledged as soon as possible
- Investigated promptly
- Treated confidentially until a fix is released
- Fixed with priority in a patch release if confirmed

We aim to maintain a fast and responsible disclosure process.

---

## Security Scope

This project focuses on safe parsing and transformation of untrusted LLM outputs.

Potential risks include:

- Malformed JSON injection
- Unexpected input causing parsing inconsistencies
- Edge cases in repair logic

If you identify any behavior that could lead to unsafe parsing or incorrect data interpretation, please report it.
